## Architecture map

### Backends

- The neutral command layer talks only to `CompositorBackend`. `gnome::mechanics` is used from production code only inside the GNOME driver. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- Backend choice: a forced `SPAWN_AT_BACKEND=x11` or `sway`; otherwise GNOME if `XDG_CURRENT_DESKTOP` has GNOME and D-Bus connects; otherwise X11. **Sway is never selected automatically.** Source: `docs/DESIGN_SWAY.md`, "7. Selection: never automatic".
- Non-GNOME Wayland, or an unknown session, with no forced backend **is an error** (`registry::unsupported`, `src/platform/linux/registry.rs:83`). A real X11 session on any desktop still gets X11. Source: `CHANGELOG.md`, "[0.2.0-beta.5] Changed".
- `install.sh` asks first on an unsupported desktop and sets `SPAWN_AT_BACKEND=x11` on the installer child only. Source: `docs/DESIGN_PLATFORMS.md`, "3. Where platform assumptions leak", Leak 11.
- The login autostart entry runs `<binary> update --check --headless`. `main.rs` returns from `Commands::Update` before `init_backend()`, so it needs no backend and its content does not depend on the desktop. Evidence: `src/config.rs` (`autostart_entry_content`), `tests/unsupported_desktop_cli_test.rs`. Recorded 2026-10-15.
- The Sway backend is `src/platform/linux/sway/` (`ipc`, `types`, `command`, `matching`, `client`, `place`, `mod`). It uses `std` sockets and the `serde_json` already present, no new dependency. Source: `docs/DESIGN_SWAY.md`, "8. IPC" and "12. Implementation status".
- The Sway module exists only on Linux, so the non-Linux `cargo check` jobs (`check-other-os`) do not compile it. Source: `docs/DESIGN_SWAY.md`, "12. Implementation status".

### Shared code

- Ready-wait exists twice, in Rust (`crates/spawn-at-core/src/ready_wait.rs`) and in JavaScript (`assets/gnome/modern/ready_wait.js`). Shared vectors in `tests/ready_wait_vectors` tie them together. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- Extension protocol numbers 4 and 5 are known only to `HelperNeed::min_protocol` (`src/platform/capability.rs:54`) and the GNOME driver's own constants.
- `/proc` process ancestry lives once, in `src/platform/linux/process_tree.rs`.
- `spawn-at-verify` has `spawn-at-core` only as a dev-dependency (`crates/spawn-at-verify/Cargo.toml`) and treats the binary as a black box. Its display and log probing is GNOME and Linux tooling.
- More: `docs/CODE_LAYOUT.md` for the layout, `docs/DESIGN_PLATFORMS.md` section 5 for feasibility per target.

### Documentation site

- The site is Starlight on Astro, with exact versions in `docs-site/package.json` (Starlight 0.42.6, Astro 7.4.0).- The CLI reference pages in `docs-site/src/content/docs/reference/` are generated by `cargo xtask docs-cli-reference` from `--help` and are not committed (only `reference/index.md` is). A missing binary or a command with no page fails the build. Source: `crates/xtask/src/docs_cli.rs`.
- Every hand-written page ends with `## Sources`. `docs-check-src` also rejects a missing title, a duplicate `# ` title, a page missing from the sidebar, `.md` links, a config without `smartypants: false` and the text in `FORBIDDEN` (`crates/xtask/src/docs_check.rs`).
- The site makes no third-party request: system fonts, no CDN scripts, no analytics, Astro telemetry off (`ASTRO_TELEMETRY_DISABLED=1`). `docs-check-html` enforces it.
- `docs.yml` pins every action by the commit SHA behind its tag. `actions/setup-node` has the same pin as `ci.yml`, with the Node major from `docs-site/.nvmrc`.
- Doc fixes that rustdoc needs are comment-only and are proven with `scripts/check-comment-only-product.sh <rev>`.
- Project documents: `cargo xtask docs-mirror` (a step of `docs-site`, before `docs-check-src`) writes 14 files of `docs/` to `docs-site/src/content/docs/project/`. They are not committed (only `project/index.md` is). `TEST_LOG.md` and `RELEASE_NOTES_*.md` are excluded, and a new `docs/*.md` in neither list fails the run. Source: `crates/xtask/src/docs_mirror.rs`.
- The mirror also links `6.NN` mentions (outside headings, code and links) to the pages in `experiments/`. On 2026-10-21 it made 130 links and left 5 mentions unlinked: `6.25` four times (only `6.25a/b/c` have pages) and `6.30` (no page).
- A mirrored file must pass the page rules too: no home path, no owner's name, no bare `<tag>` outside backticks (the HTML drops it), no dash glued to a word. `is_mirrored` in `docs_check.rs`.
- Long tables: `docs-site/src/integrations/records.mjs` rewrites a `<table>` of the built HTML as one card per row. It runs after Starlight (the Pagefind index is made from the table text) and before `code-breaks.mjs`. The rules are in `writing-docs.md`, "Long tables as records".
- A list whose keys all start with a whole number is steps (`stepKey`). A cell of 240 characters or more converts a table on `project/` pages. A field over `TITLED_MIN = 400` characters makes the whole list titled cards. `tests/records_test.js` runs in the `node --test` step.
- `docs-check-src` fails on a table cell over `MAX_CELL_CHARS = 1200` characters on every page except `experiments/`. On 2026-10-20 the longest cell left in `docs/` had 581.

## Install and release

- The version comes from the git tag at build time (`build.rs`, `git describe --tags --exact-match`). An exact tag prints `spawn-at <version>`; otherwise the binary prints `DEV BUILD`. Source: the contributor rules, "Versions and releases".
- `install.sh` is fetched from `main`, so **a merge ships it at once**. Binary changes ship with the next tag. Source: `CHANGELOG.md`, "[0.2.0-beta.3]" intro.
- A tag containing `-` makes `release.yml` publish a pre-release.
- `release.yml` starts with `cargo xtask check-release-version <tag>` (4 `Cargo.toml` + 4 `Cargo.lock` entries must equal the tag, `crates/xtask/src/release.rs`), takes the `## [<version>]` section of `CHANGELOG.md` as the release body when there is one (`cargo xtask release-notes`), and has a `workflow_dispatch` dry run. Only the `softprops/action-gh-release` step publishes, guarded by `github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v')`; `test_release_yml_publishes_only_for_a_tag_push` pins that guard. Checked by reading, PyYAML parsing (it found a `): ` plain-scalar error in the first draft) and the unit tests; **the workflow has not run on GitHub**, and a dispatch only works once the file is on the default branch. No `actionlint` on the dev machine. Recorded 2026-10-21.
- `spawn-at update` picks the release asset named for its own target triple (`SPAWN_AT_TARGET`, `src/update.rs:607`). Source: `CHANGELOG.md`, "[0.2.0-beta.4] Changed".
- The update channel `all` is a deprecated alias of `beta` (`src/update.rs:125`).
- `spawn-at install` skips the log-out question when the deployed extension is byte-identical, active, and older than the running shell. The log-out is always the last action. Source: `CHANGELOG.md`, "[0.2.0-beta.3] Added / Fixed".

## GNOME and Wayland behavior

- Wayland has no generic "move another client's window" protocol, so every compositor needs its own IPC or script. Public knowledge, unverified here. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- The GNOME extension exposes only a protocol number over D-Bus, no content hash, so "is the running extension current" needs file facts (`logout.rs`).
- Measured delayed-paint, cloak budget and min-size behavior of GNOME 46: `docs/TEST_PLAN.md`, sections 5 and 6. Raw logs: `docs/TEST_LOG.md`.
- Sway 1.9 (headless): the IPC frame is a 14-byte header plus JSON, and the real JSON shapes are recorded. Source: `docs/DESIGN_SWAY.md`, "2. Verified facts about Sway".
- Sway `--size` is the whole container, as on GNOME. It is corrected once after `resize set` for the border and title bar, and a window raised to its minimum is re-anchored with its real size. Source: `docs/DESIGN_SWAY.md`, "12. Implementation status".
- Sway `state` in `query windows` is `normal` or `fullscreen`, and scratchpad windows list as `minimized`. Source: the same section.
- GNOME marks an extension OUT OF DATE and never loads it when the running Shell major is not in `shell-version`, so its D-Bus object never appears and the CLI sees `UnknownMethod: Object does not exist at path /org/gnome/Shell/Extensions/SpawnAt`. Evidence: the owner's `gnome-extensions info spawn-at@harsh.local` on Ubuntu 26.04 / Shell 50.1 showed `Enabled: Yes`, `State: OUT OF DATE` while `assets/gnome/modern/metadata.json` listed 45 to 48. Fixed by listing 49 and 50 (`src/platform/linux/gnome/diagnose.rs` now names this case). Recorded 2026-10-21.
- GNOME 50.1 (Ubuntu 26.04, Wayland) works with the current modern extension, protocol 2 or newer (the extension code reported 6 then, 7 since #84): after adding "49" and "50" to the installed `metadata.json` and logging in again the state was ACTIVE, and `spawn -o 100 100 gnome-terminal` and `-o 1000 100` placed the window at (100, 140) and (1000, 140). **Verified by the owner by hand, not by Claude Code**; GNOME 49 was not run. Recorded 2026-10-21.
- **GNOME 50.1 (Wayland) failed 9 of 36 required `release-gate` cases** in the one live run (2026-10-21, clean build `c2437c7`, Ubuntu 26.04, one monitor, test window only): 16 passed, 9 failed, 4 skipped, 7 `Both`-kind cases await a human verdict. Every failure is a "request below the minimum size" case (fixture minimum 300x200): the window came out 300x300 (`dh=+100`, and `dy` follows for bottom anchors). The extension's own trace says `SET_SIZE_CLAMPED requestedSize=(300x200) reportedMinSize=(0x300)`, so the Shell reported a minimum height of 300 (the fixture's initial height) where the fixture enforces 200. A race between the first commit and the min-size read is a hypothesis, **not investigated**. The 4 `cloak/delayed-paint` cases are skipped on Shell 50 by their spec (`gnome = "42-48"` in `verify/cloak/`), and a skipped required case never counts as a pass, so the platform is not qualified. Hence `install_notice::PARTLY_TESTED`, not `VERIFIED`. Not re-run on 46, so whether the same cases pass there is unknown here. Recorded 2026-10-21.
- `-o` / `-p` without `--anchor` is counted from the top-left of the `--area` rectangle, the work area by default, so `-o 100 100` lands at y = 100 + the top bar (40 px on the owner's machine): (100, 140). Not an off-by-40 bug. The success line now prints the offset, the area, its origin and the screen position (`RequestedPlacement` in `src/diagnostics.rs`). Evidence: `docs-site/src/content/docs/concepts.md`, "Position"; the owner's log. Recorded 2026-10-21.
- A named arm that no window claims (the app forwards to an already visible instance, so no window is created) stays queued for `ARM_EXPIRY_MS` = 15 s and the next window of that app is placed from it, because `_claimInstructions` takes `queue.shift()`, the oldest. The CLI gives up after about 4 s (2 s claim wait, then 2 s poll, `window_timeout_ms` default 2000). Fixed for the modern tree in #84: `spawn` withdraws its own entry with `DisarmEntry` (protocol 7). A show inside the CLI's own ~4 s wait after a no-window arm is still served from the older entry. Evidence: `assets/gnome/modern/extension.js` (`_arm`, `DisarmEntry`), `tests/stale_arm_test.js`, `src/commands/spawn.rs` (`withdraw_arm`). The 15 s, the oldest-first claim and the ~4 s are read from the code; the fix was tested with node and D-Bus stubs, and a live run on GNOME 50 is unverified. Recorded 2026-10-21.
- While any arm is live, every new window is cloaked and held until it settles (`_hasArmedSpawns()` in `_handleWindowCreated` and `_handleActorMap`), so a stale arm also delays unrelated windows. Read from `extension.js`, not run. Recorded 2026-10-21.
- A D-Bus method has no optional arguments: calling a 3-argument method with 2 arguments fails with `InvalidArgs: Type of message, "(ss)", does not match expected type "(sss)"`. Checked on a private `dbus-run-session` bus with a gjs object from `Gio.DBusExportedObject.wrapJSObject`, the extension's own mechanism. So a changed method signature breaks every installed CLI, and a new capability is a new method gated on `ProtocolVersion`. Recorded 2026-10-21.
- A failed `ProtocolVersion` read used to count as protocol 0, so a missing extension printed "protocol mismatch ... log out and back in". `arm` and `prepare_claim_wait` now keep a failed read apart, and `diagnose.rs` picks not installed, OUT OF DATE (checked before disabled), disabled, old protocol or not loaded. Only a loaded extension with an older protocol gets the "load the updated extension" hint. Unverified on a live Shell. Recorded 2026-10-21.

- A headless update that rewrites the extension files used to say nothing (#87). Now `perform_upgrade(release, headless)` takes the deployed files before and after the child `install` (`needs_logout::classify`), and with no terminal and a Wayland session sends one `org.freedesktop.Notifications.Notify` and writes `$XDG_STATE_HOME/spawn-at/needs-logout` (`protocol=`, `fingerprint=`). `arm` (so `spawn`) prints one hint while the loaded protocol is lower and removes the marker when it has caught up. A change that keeps the protocol number (metadata only) is announced but never hinted, because the extension exposes only a protocol number. Evidence: `src/platform/linux/gnome/needs_logout.rs`, `src/update.rs` (`perform_upgrade`). Run end to end in a temp tree on a private bus (stand-in new binary, fake curl and loginctl, gjs notification stub), not on a real login. There is **no `doctor` command** in the CLI, so only `spawn` shows the hint. Recorded 2026-10-21.
- The marker path is injected into `GnomeWaylandDriver` (`logout_marker`): `new()` sets it, `from_proxy` (tests) leaves it `None`, so a unit test never reads or removes a marker in the real `~/.local/state`. Recorded 2026-10-21.

## Testing and fixtures

### Running and counting

- `node --test tests/*.js` includes the installer test that runs `install.sh` against a stand-in curl and `spawn-at`. A rule of "never execute `install.sh`" therefore also **rules out running that file locally**. CI runs it. Recorded 2026-10-18.
- Run `spawn-at-verify` per binary, not as a bare workspace number: `cargo test -p spawn-at-verify --features tui,fixture` (5 tests stay ignored). Counts: `docs-site/src/content/docs/testing.md`, "Test counts".
- A live `spawn-at-verify run` leaves the extension's trace logging **on**: the harness only ever sends `SetLogging(true)` (`ext_logging.rs`) and the extension logs nothing when logging is turned off, so the journal does not confirm `gdbus call --session --dest org.gnome.Shell --object-path /org/gnome/Shell/Extensions/SpawnAt --method org.gnome.Shell.Extensions.SpawnAt.SetLogging false`, which is how it was switched back after the run. The extension also writes the same lines to `$XDG_STATE_HOME/spawn-at/session.log` (`assets/gnome/modern/logger.js`, rotated to `session.log.old`), so a live run leaves about 170 KB in the real state directory. A release-gate run wrote 954 `[spawn-at-time]` lines plus 6 gnome-shell `Tried to ping window ... with a bad serial! Not allowed.` warnings (for the windows closed at the end) to the user journal. `release-gate` refuses a dirty build, and any `run`, even `--dry-run`, writes `./verify-results/<ts>/` in the current directory (gitignored). Recorded 2026-10-21.
- To run `spawn-at update --headless` end to end without GitHub, the real session or the real home: `dbus-run-session` for a private bus, a fake `curl` first on `PATH` (the updater only runs `curl` for `/releases`, `/releases/latest` and the asset download, `src/update.rs`), a fake `loginctl` to flip Wayland and X11 (`is_wayland_session` reads `loginctl show-session ... -p Type`), `HOME`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME` and `TMPDIR` in one `mktemp -d`, a copy of the debug binary as the "installed" one (the update overwrites `current_exe()`), and a shell script as the "new" binary. gjs can stub `org.freedesktop.Notifications` and, with `import {DBUS_IFACE} from '.../assets/gnome/modern/dbus.js'` under `gjs -m`, the extension's own D-Bus object. Set `GIO_USE_VFS=local` or gvfs tries to mount under `/run/user`. Recorded 2026-10-21.
- Count tests with `cargo test --locked -p <crate> [--features ...] -- --list`, which runs nothing (`--ignored` lists the ignored ones). For Node, run one `node --test` per `tests/*_test.js`, because `node --test tests/*.js` also counts the helper `tests/gi_loader.js` as 1 test. Recorded 2026-10-20.
- The totals of the test counts are in one table, in `docs-site/src/content/docs/testing.md`. `docs/TEST_PLAN.md` section 1.2 has the breakdown per binary. Nothing else should quote them.

### Sway tests

- Live Sway tests run only in a private headless Sway, started by `scripts/sway-headless.sh`. `scripts/sway-live.sh` had 62 checks and 0 failed on 2026-10-15 (Sway 1.9). Source: `docs/TEST_PLAN.md`, section 7.2.
- The Sway golden frames and JSON fixtures were recorded from a real Sway 1.9 (`tests/fixtures/sway/`).
- `scripts/verify-sway.sh` runs the runner on a private headless Sway. The runner blocks every test unless `SWAYSOCK` is in a marked `spawn-at-sway.*` directory. Evidence: `docs/TEST_PLAN.md`, section 7.4.

### The verify catalog

- Which commands are tested, at which tier, and how flicker is measured: `docs/TEST_COVERAGE_AUDIT.md`, audit of 2026-10-15. `defocus`, `restore` and `minimize` had no behavior test then.
- Specs that act on an existing window (`schema_version = 2`) launch their own fixture, act only on `--id ${name}` of a window the runner recorded, tear down on every path, and need the tag `moves-focus` (left out of `quick`). A backend the spec does not list is skipped as "unsupported on this backend". Source: `docs/DESIGN_RUNNER_SETUP.md`.
- The catalog has 22 such specs in `verify/{queries,transforms,focus,robustness}/`. 15 passed on Sway 1.9, the 7 GNOME-only ones were skipped, none has run on GNOME. Evidence: `docs/TEST_PLAN.md`, section 7.5.
- A fresh tiled Sway window is work-area sized, so a position-only transform keeps that size. That is why `transforms/reposition-by-id` is GNOME only.
- `catalog_golden_test` compares only the original 45 entries, so specs may be added but none of the 45 may change.
- The extension's trace line is `[spawn-at-time] +<ms>ms | TAG win=[id=N pid=N class="..." ...] key=value`. `+<ms>` is the extension's own clock from its first log line, not the journal timestamp (the idle-callback flush time). `WINDOW_CREATED` and `ACTOR_MAP` are logged for every window, so a reader must filter by id. What each command logs: `docs/DESIGN_RUNNER_SETUP.md`, section 5.5. Fixtures: `crates/spawn-at-verify/tests/fixtures/real_{transform,focus}_existing_window_trace.log` (owner's journal, 2026-10-16).
- Per-action trace capture (`runner/action_trace.rs`, 2026-10-16) is off unless `RunOptions::action_trace` is set, because it enables the timing log over D-Bus and reads the user journal, which `cargo test` on a GNOME desktop must not do. Slices are whole seconds wide, so an action's lines are separated by a floor. Not run on real GNOME.

### The TUI

- The sidebar order is `category_rank` in `tui/app/state.rs` and nowhere else (test `tests/tui/sidebar_order.rs`). Commit `734ffe5` changed the drawer sections, not this.
- The focus return after an attended test is `TuiApp::return_focus_to_terminal`. It gives focus back to the terminal so that the verdict keys reach the TUI and not the test window, for version 1 and version 2 specs. The outcome on GNOME is unverified.
- A ratatui 0.29 `Paragraph::scroll((n, 0))` overflows for a huge `n` (`paragraph.rs:483`), a panic in debug builds. The TUI stored `u16::MAX` for `G`, so the next draw panicked with no panic hook and left the terminal raw. Offsets are now clamped at the key and at the draw, and `install_panic_hook_with` restores the terminal (test `tests/tui/drawer_scroll.rs`). 2026-10-16.
- The TUI enables no mouse capture, so wheel notches arrive as Up and Down keys. The old loop read one event per draw, so a flick built a backlog (100 events were 100 draws, counted in `tests/tui/scroll_work.rs`). A frame now drains all pending events and draws once.
- The drawer cache (`DrawerCache`) is keyed on the test, width, raw or compact, and a hash of what the sections read, never on the scroll offset. A new thing the drawer shows must go into `content_key` or call `invalidate_drawer_cache`.
- A key only records state. Slow work is a `Pending` step that `tui/mod.rs` runs after the next `draw`, because the test run and the teardown run on the UI thread (about 190 ms for the automatic phase and about 1.1 s for the teardown, measured against test doubles).
- One focus memory, `SetupSession::remember_focus` and `restore_focus` (`runner/owned.rs`), is used after the automatic phase and in teardown. `guard_user_window` refuses any non-`focus` command that names that id. Whether focus really lands on GNOME is unverified.

## Gotchas

### Build, update and tests

- `spawn-at update` on GNOME runs the new binary from a temp directory as `install --skip-bin --headless` and deletes it afterwards, so `current_exe()` in that child is a path that disappears. The login entry's `Exec=` therefore comes from `login_entry_exe` (`src/platform/installer.rs:61`: installed copy first, `current_exe` last). An updater started from a binary outside both bin dirs still gets the temp path. Fixed in the 0.2.1 batch (#48), unverified live. Recorded 2026-10-18.
- The update cache (`last_check_time`, `cached_*_version`) lives in the `[update]` table of the user's config file, so moving it would change where config keys live. `update --check` in a terminal no longer saves it (#49); `update`, `update --headless` and the silent `--check --headless` do. Recorded 2026-10-18.
- The binary embeds its commit or tag. After every commit run `cargo build -p spawn-at` before a verify batch, or preflight blocks it as `Stale binary`. Source: `verify/README.md`, "4. Preflight Gate & Binary Freshness".
- `LinuxBackend` forwards `Driver::arm` and `Driver::disarm_entry` but **not** `Driver::disarm`, so the `disarm` call in `spawn.rs` for a command that fails to start reaches the trait default (`Ok(false)`) on Linux. Forwarding it would call the whole-queue `DisarmSpawn` and wipe other launches' entries. `test_linux_backend_forwards_disarm_entry_but_not_disarm` pins both. Recorded 2026-10-21.
- The Rust D-Bus stub tests connect with `zbus::Connection::session()`, which is the live session bus when run from a desktop terminal. Run them as `dbus-run-session -- cargo test ...` to keep them on a private bus. In the node tests the `GLib.timeout_add` mock fires every timer within 5 ms (`tests/gi_loader.js`), so a test that needs an arm to stay queued must not yield to the event loop. Recorded 2026-10-21.
- Spawning a GNOME D-Bus stub on the same zbus connection as the client hangs unless `ProtocolVersion` is read before the first method call (`gnome/tests_control.rs`, `driver_for`).
- `spawn --focus`, `--no-focus` and `--defocus` are **parsed but never read**: `run_spawn_with` always uses `FocusIntent::Exclusive`, pinned by `test_spawn_focus_modifiers_have_no_effect_today`.
- Bash holds a trap back while a foreground child runs, so a wrapper script must run the child in the background and `wait`.
- `run_spawn_with` is one function of about 550 lines (`src/commands/spawn.rs:90-642`, 2026-10-21). Splitting it was a prerequisite for a second ready-signal model. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- Sway `--no-wait` **still waits for the placement**, because the pipeline awaits `post_spawn` in every mode, and `post_spawn` waits a fixed 5 s. Only the first entry of a batch is placed (the X11 driver does the same). Source: `docs/DESIGN_SWAY.md`, "12. Implementation status".
- `escalate.rs` has macOS and Windows branches that **have never been run**. They are compiled: CI `check-other-os` runs `cargo check --locked --workspace` for `x86_64-pc-windows-gnu`, `x86_64-apple-darwin` and `aarch64-apple-darwin`.- xtask tests that write a script and then run it must not run in parallel: a child forked while the script is still open for writing gives "Text file busy" (os error 26) on exec. `docs_cli.rs` serializes them with `SCRIPT_LOCK` (2026-10-16).

### rustdoc

- `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --workspace --locked` fails on one item: `<INDEX>` in the doc comment of `--monitor` (`src/cli/args.rs:52`), which is also clap's `--help` text. It cannot be fixed comment-only without changing `--help`, so the docs build adds `-A rustdoc::invalid_html_tags` (`RUSTDOC_FLAGS`, `crates/xtask/src/docs_site.rs:24`). An owner decision is open.
- `cargo doc` documents a binary crate with its private items, so a broken link in any private doc comment of `spawn-at` fails it. It also leaves old crates in `target/doc`; `docs-site` clears it first.

### Documentation site: build

- Starlight does not rewrite links, so pages link `/spawn-at/<slug>/`; a relative `x.md` link gives a 404. A page named `api` would build to `/api/index.html`, where the rustdoc output is copied, so that page is `rustdoc`.
- `autogenerate` cannot sit on a group directly (since Starlight 0.39): use `items: [{ autogenerate: { directory } }]`.
- `markdown.smartypants: false` still works in Astro 7.4.0 but prints a deprecation warning. With it on, the two hyphens of `--pivot` become an en dash, which `docs-check-html` catches.
- `npm ci --ignore-scripts` is enough to build. mdBook has no link checker, so `docs-check-html` checks internal links and `#id`s without network.
- GFM splits a table cell at every `|` without a backslash, even inside a code span, so write `\|` in code in a table row. Three rows of `docs/` lost cells this way until PR 67 (2026-10-19), and **`docs-check-src` does not catch it**.
- Markdown inside raw HTML renders only when blank lines surround it. Converting a table in the built HTML, as `records.mjs` does, avoids writing such wrappers from the mirror.

### Documentation site: styling

Measured with Chrome 153 and Linux fallback fonts, 2026-10-19 to 2026-10-21.

- A table whose first column only counts rows (1, 2, 3) has no content in that column. Key it by the first column that names the row, and keep numbers only where other text refers to them (`6.NN`, "gap 15", "P12"). 2026-10-21.
- A piece of code over 20 characters is an inline-block (`.code-any`), and with the inherited line height its chip was 24.47 px against 17.72 px for short code. `custom.css` now gives it `line-height: normal` and 0.1em block padding, and `text-box: trim-both text` where supported so wrapped pieces keep their line pitch. 2026-10-21.
- A `.code-any` piece is wider than a column that has no padding, because the chip adds 0.3em on each side. `records.css` shortens it by `0.6em` in a card field.
- Starlight sets `font-size: inherit` for `code` in headings, and the monospace face is wider, so it reads larger; `custom.css` uses `0.9em` there.
- The browser's default bold (`bolder`) is 700. `custom.css` sets `strong` to 600. A try at 500 was nearly invisible next to the 400 text.
- `--sl-text-body` is read only by Starlight's Card and ContentNotice, so setting it never changed body text. Block spacing is `--sl-content-gap-y` as the margin-top of every sibling block. A heading's top margin sits on its `.sl-heading-wrapper` div.
- `--sl-font-mono` is not defined unless a site sets it; use `--sl-font-system-mono`. Starlight indents every `<dd>` by 1rem; `records.css` resets it.
- A selector such as `.record-key :not(pre) > code` matches nothing when the `code` is a direct child of `.record-key`; write `.record-key code`.
- The short fields of a card come first in the HTML (`records.mjs`), so keyboard focus follows the order on screen. CSS `order` would split the two (2026-10-20).
- Starlight's table is `display: block; overflow: auto`, so CSS alone cannot make a table with short cells fill the column. `toc-toggle.js` marks tables whose content fits with `data-fit`, and `tables.css` centres those at their own width. An overflowing table stays the scrolling block, because the scroll hint needs it.
- With the table of contents hidden, `--sl-content-width` is 50rem for everything. 89 of 98 pages had a table, code block or aside sticking out right of the text before that, and none after (2026-10-20).
- Tables and code blocks that scroll sideways get CSS-only edge shadows (`scroll-hints.css`, `background-attachment: local`). At 390 px wide, 76 of 98 pages have such a block, and no page scrolls sideways as a whole (2026-10-20).
