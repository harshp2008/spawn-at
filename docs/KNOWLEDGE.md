## Architecture map

- The neutral command layer only talks to `CompositorBackend`; `gnome::mechanics` is used from production code only inside the GNOME driver. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering". Details: its "4. Proposed capability model".
- Backend choice: forced `SPAWN_AT_BACKEND=x11` or `sway`, else GNOME if `XDG_CURRENT_DESKTOP` has GNOME and D-Bus connects, else X11. Non-GNOME Wayland (or unknown session type) without a forced backend is an error since the unsupported-desktop check (`registry::unsupported`), which is on `main` only: it does not exist in v0.2.0-beta.3 or v0.2.0-beta.4 (`git show v0.2.0-beta.4:src/platform/linux/registry.rs` has no `unsupported`; corrected 2026-10-16, this entry said it as if released); a real X11 session on any desktop still gets X11; `install.sh` asks first and sets `SPAWN_AT_BACKEND=x11` on the installer child. Source: `docs/DESIGN_PLATFORMS.md`, "3. Where platform assumptions leak", Leak 11; `CHANGELOG.md`, "[Unreleased] Changed"; `docs/DESIGN_SWAY.md`, "7. Selection: never automatic".
- The login autostart entry runs `<binary> update --check --headless`, which needs no backend (`main.rs` returns from `Commands::Update` before `init_backend()`; `update.rs` `run_update` calls no registry code), so it works on an unsupported desktop and its content does not depend on the desktop or on `SPAWN_AT_BACKEND`. Evidence: `src/config.rs` `autostart_entry_content`, tests `autostart_file_tests`, `tests/unsupported_desktop_cli_test.rs`. Source: `docs/DESIGN_PLATFORMS.md`, "3. Where platform assumptions leak", Leak 5; recorded 2026-10-15.
- Sway is never selected automatically; only the forced value `sway` selects it. Source: `docs/DESIGN_SWAY.md`, "7. Selection: never automatic"; `docs/TEST_PLAN.md`, "7.1 Unit and integration tests".
- Sway backend files (`src/platform/linux/sway/`: `ipc`, `types`, `command`, `matching`, `client`, `place`, `mod`) and their roles: `docs/DESIGN_SWAY.md`, "12. Implementation status". It uses `std` sockets plus the `serde_json` already present, no new dependency ("8. IPC: hand-roll, no new dependency").
- The Sway module exists only on Linux, so the non-Linux `cargo check` runs and `check-other-os` do not compile it. Source: `docs/DESIGN_SWAY.md`, "12. Implementation status".
- Ready-wait exists twice, in Rust (`crates/spawn-at-core/src/ready_wait.rs`) and JS (`assets/gnome/modern/ready_wait.js`), tied by shared vectors in `tests/ready_wait_vectors`. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- Extension protocol numbers (4, 5) are known only to `HelperNeed::min_protocol` in `capability.rs` and the GNOME driver's own constants. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- `/proc` process ancestry lives once, in `linux/process_tree.rs` (it existed twice before step 2). Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- `spawn-at-verify` has `spawn-at-core` only as a dev-dependency (`crates/spawn-at-verify/Cargo.toml`, `[dev-dependencies]`; corrected 2026-10-16, this entry said "depends only on") and treats the binary as a black box, but its display and log probing is GNOME/Linux tooling. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- Code layout overview: `docs/CODE_LAYOUT.md`. Per-target feasibility: `docs/DESIGN_PLATFORMS.md`, "5. Feasibility per target".
- Long tables on the docs site (2026-10-19): `docs-site/src/integrations/records.mjs` rewrites a `<table>` of the built HTML as one card per row (`ul.records > li.record`: the key, then a `dl` of labelled fields, each `field-short` at 40 characters of text or fewer, else `field-long`); a list whose keys all start with a whole number is an `ol.records-steps` (big number plus note, the rule is `stepKey`); on `project/` pages when a cell has 240 characters or more, anywhere with a `site:` comment on the line above the table (`records`, `records key=N`, `records style=steps|cards`, `table`). It runs after Starlight (the Pagefind index is made from the table text) and before `code-breaks.mjs`. `docs_check.rs` (`directive_problems`) validates the comments through the mirrored pages (that `style=steps` keys are numbers is checked by the build only); `tests/records_test.js` runs in the `node --test` step. As of the cards change (2026-10-19) 35 tables convert, 1 of them as steps (the migration plan of `docs/DESIGN_PLATFORMS.md`; its "where assumptions leak" list has keys "Leak N", so it is cards); the numbered contract list of `docs/TEST_PLAN.md` section 6.1 is `style=cards`, its numbers are labels. Source: `docs-site/src/styles/records.css`, `docs-site/src/content/docs/contributing/writing-docs.md`, "Long tables as records".

## Install and release

- The version comes from the git tag at build time (`build.rs`, `git describe --tags --exact-match`). On an exact tag the binary prints `spawn-at <version>` with no commit id; otherwise `DEV BUILD` with `Previous Commit ID`. Source: `CLAUDE.md`, "Versions and releases"; `CHANGELOG.md`, "[Unreleased] Fixed" (preflight).
- `install.sh` is fetched from `main`, so a merge ships it at once; binary changes ship with the next tag. Source: `CHANGELOG.md`, "[0.2.0-beta.3]" intro.
- A tag containing `-` makes `release.yml` publish a pre-release. Source: `CLAUDE.md`, "Versions and releases".
- `spawn-at update` picks the release asset named for its own target triple (`SPAWN_AT_TARGET`). Source: `CHANGELOG.md`, "[0.2.0-beta.4] Changed"; `build.rs`.
- Update channel `all` is a deprecated alias of `beta`. Source: `docs/TEST_PLAN.md`, "Re-measured 2026-10-14 after the update-channel fix".
- `spawn-at install` skips the log-out question when the deployed extension is byte-identical, active, and older than the running shell. The log-out is always the last action. Source: `CHANGELOG.md`, "[0.2.0-beta.3] Added / Fixed".
- Beta.4 changed no file under `assets/gnome/` or `install.sh` relative to beta.3. Source: `CHANGELOG.md`, "[0.2.0-beta.4]" intro; `docs/RELEASE_NOTES_0.2.0-beta.4.md`.
- Documentation site (2026-10-16), the rules: (1) the CLI reference pages under `docs-site/src/content/docs/reference/` are generated by `cargo xtask docs-cli-reference` from the built binary's `--help` and are **not committed** (`.gitignore`; only `reference/index.md` is tracked), so they cannot drift; a missing binary, a listed command with no page, or a sidebar in `docs-site/astro.config.mjs` without `autogenerate: { directory: 'reference' }` fails the build. (2) Every hand-written page ends with `## Sources`; `docs-check-src` also rejects a page without front matter `title`, a duplicate `# ` title, empty pages, a page missing from the sidebar, `.md` links, a config without `smartypants: false`, a missing environment page and forbidden text (the list `FORBIDDEN` in `crates/xtask/src/docs_check.rs`). (3) Doc fixes needed for rustdoc are comment-only and are proven with `scripts/check-comment-only-product.sh <rev>`. (4) `docs.yml` pins every action by the commit SHA behind its tag (annotated tags resolved, each checked with `gh api`); `actions/setup-node` has the same pin as `ci.yml`, with the Node major from `docs-site/.nvmrc`. (5) The site makes no third-party request: system fonts, no scripts from a CDN, no analytics, Astro telemetry off (`ASTRO_TELEMETRY_DISABLED=1`); `docs-check-html` enforces it. (6) Since 2026-10-16 the site is Starlight (Astro) with exact package versions in `docs-site/package.json`; it replaced mdBook 0.5.4 (the playground-element rule in `docs-check-html` stayed as a guard). Source: `crates/xtask/src/docs_*.rs`, `.github/workflows/docs.yml`, `docs/CODE_LAYOUT.md`, "Documentation site".
- Project documents on the site (2026-10-19): `cargo xtask docs-mirror` (a step of `docs-site`, before `docs-check-src`) writes 13 files of `docs/` to `docs-site/src/content/docs/project/` (not committed; only `project/index.md` is tracked). The list of mirrored files and their sidebar order, and the excluded ones (`TEST_LOG.md`, `RELEASE_NOTES_*.md`), are in `crates/xtask/src/docs_mirror.rs`; a new `docs/*.md` in neither list fails the run. A mirrored file must also pass the page rules, so it cannot hold a home path, the owner's name, a bare `<tag>` outside backticks (the HTML drops it) or a dash glued to a word (`docs-check-html`). Source: `crates/xtask/src/docs_mirror.rs`, `docs_check.rs` (`is_mirrored`).

## GNOME and Wayland behavior

- Wayland has no generic "move another client's window" protocol; every compositor needs its own IPC or script (public knowledge, unverified here). Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- The GNOME extension exposes only a protocol number over D-Bus, no content hash, so "is the running extension current" needs file facts (`logout.rs`). Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- Measured delayed-paint, cloak budget and min-size behavior of GNOME 46: `docs/TEST_PLAN.md`, "5. Delayed-Paint Calibration & Cloak Budget Analysis" and "6. Min-size contract"; raw logs in `docs/TEST_LOG.md`.
- Sway (1.9, headless) facts: IPC frame is 14 bytes; real JSON shapes are recorded. Source: `docs/DESIGN_SWAY.md`, "2. Verified facts about Sway" and "Real JSON shapes".
- Sway placement: `--size` is the whole container (as on GNOME), corrected once after `resize set` for border/title bar, and a window raised to its minimum is re-anchored with its real size. Source: `docs/DESIGN_SWAY.md`, "12. Implementation status"; `docs/TEST_PLAN.md`, "7.1".
- Sway `state` in `query windows` is `normal` or `fullscreen`; scratchpad windows list as `minimized`. Source: `docs/DESIGN_SWAY.md`, "12. Implementation status".
- Sway cannot read the pointer, so `--anchor cursor` and `--monitor cursor` use (0, 0); maximize, minimize, restore and defocus are unsupported. Source: `docs/DESIGN_SWAY.md`, "12. Implementation status".
- The Sway one-frame flash before placement is accepted but not measured. Source: `docs/DESIGN_SWAY.md`, "5. Flicker-free strategy" and "12. Implementation status".

Not run on real GNOME.
- TUI sidebar order is `category_rank` in `tui/app/state.rs` and nowhere else; commit 734ffe5 ("reorder drawer") changed the drawer sections, not this, so FOCUS stayed 5th until 2026-10-16 (now PREFLIGHT, FOCUS, QUERIES, ROBUSTNESS, PLACEMENT, CLOAK, TRANSFORMS, GENERAL; `tests/tui/sidebar_order.rs`). The Result box shows the recorded terminal, each `focus` exit code and what had focus afterwards. Sway chain test: `scripts/focus-chain-sway.sh`. GNOME outcome: unverified until the owner pastes the lines.
- Gotcha (2026-10-16): a ratatui 0.29 `Paragraph::scroll((n, 0))` adds `n` to a row index and overflows for a huge `n` (`ratatui-0.29.0/src/widgets/paragraph.rs:483`, a panic in debug builds). The TUI used to store `u16::MAX` for `G`, so the drawer's next draw panicked with no panic hook: the terminal stayed raw and nothing answered, Escape included. Offsets are now clamped at the key (`TuiApp::scroll_down/up/to_end`, using `scroll_max` that every draw sets from the wrapped row count) and at the draw; `install_panic_hook_with` restores the terminal. Test: `tests/tui/drawer_scroll.rs`.
- Gotcha (2026-10-16), scroll lag: the TUI enables no mouse capture, so a terminal sends wheel notches as Up/Down key presses (alternate scroll); the old loop read ONE event and drew once, and each draw rebuilt the drawer content, so a touchpad flick built a backlog that kept scrolling after the fingers stopped (100 events = 100 draws = 100 rebuilds, counted in `tests/tui/scroll_work.rs`). Rules now: a frame drains all pending events (`tui/events.rs`: caps, acceleration constants) and draws once; the drawer content cache (`views/drawer/mod.rs`, `DrawerCache`) is keyed on the test, width, raw/compact and a Debug-hash of what the sections read, never on the scroll offset, so a new thing the drawer shows must be added to `content_key` or call `invalidate_drawer_cache`. The main-view details pane is not cached.
- TUI verdict feedback and focus return (2026-10-16): a key only records state; slow work is a `Pending` step (`tui/app/state.rs`, `queue.rs` `run_pending`) that `tui/mod.rs` runs after the next `draw`, because `execute_single_test` and the teardown run on the UI thread (measured against the test doubles: automatic phase about 190 ms, teardown about 1.1 s when the window never leaves the list; the 50 ms poll is not the source). One focus memory: `SetupSession::remember_focus`/`restore_focus` (`runner/owned.rs`) used after the automatic phase and again in teardown (no-op if already focused); `guard_user_window` refuses any non-`focus` command naming that id. Selected-row marker fix: `marker_color` in `tests_list.rs`. Notes (not verdicts) live in `WindowTracker.notes`. Unverified on real GNOME: whether focus really lands, and how often the terminal covers the fixture. Evidence: `tests/tui/verdict_feedback.rs`.
- Gotchas found while building it: a `run` of the debug `spawn-at` is judged `Stale binary` unless the tree is clean and `target/debug/spawn-at` was rebuilt at the current `HEAD`; a stub on the same zbus connection hangs unless the first call is a property read (see above); bash holds a trap back while a foreground child runs, so a wrapper must run the child in the background and `wait`.

## Gotchas

- `spawn-at update` on GNOME runs the new binary from a temp dir as `install --skip-bin --headless` and deletes the dir afterwards, so `current_exe()` in that child is a path that disappears. The login entry's `Exec=` therefore comes from `platform::installer::login_entry_exe` (installed copy first, `current_exe` last). Residual: an updater started from a binary outside both bin dirs still gets the temp path. Evidence: `src/update.rs` `perform_upgrade`, `src/platform/linux/gnome/deploy.rs` `after_unpack`, `src/main.rs` (`login_entry_exe` call). Fixed in the 0.2.1 batch (#48), unverified live. Recorded 2026-10-18.
- The update cache (`last_check_time`, `cached_*_version`) lives in the `[update]` table of the user's config file, so moving it to a separate file would change where config keys live (a contract item). `update --check` in a terminal no longer saves it (#49); only `update`, `update --headless` and the silent `--check --headless` do. Evidence: `src/update.rs` `lookup_is_cached`, `headless_check`. Recorded 2026-10-18.
- The binary embeds its commit (or tag); after every commit `cargo build -p spawn-at` must run before a verify batch, or preflight blocks it as stale. Source: `docs/TEST_LOG.md`, "6.23 Post-reinstall live check" (Process finding); `verify/README.md`, "4. Preflight Gate & Binary Freshness".
- Plain `cargo build` / `cargo test` at the root cover only the `spawn-at` package; name the other crates. Source: `CLAUDE.md`, "Build and test commands".
- `run_spawn_with` is one function of about 524 lines at the time of writing (`spawn.rs`); splitting it was a prerequisite for a second ready-signal model. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- Only two `supports_*` capability flags are read in production (`transform.rs`, `lifecycle.rs`). Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering".
- Sway: `--no-wait` still waits for the placement, because the pipeline awaits `post_spawn` in every mode; `post_spawn` waits a fixed 5 s. Source: `docs/DESIGN_SWAY.md`, "12. Implementation status".
- Sway: only the first entry of a batch is placed (the X11 driver does the same). Source: `docs/DESIGN_SWAY.md`, "12. Implementation status".
- `escalate.rs` has macOS and Windows branches that have never been run. They are compiled: `cargo check --locked --workspace` passes for `x86_64-pc-windows-gnu`, `x86_64-apple-darwin` and `aarch64-apple-darwin` (CI job `check-other-os`; run again 2026-10-16). Corrected 2026-10-16: this entry said "never been compiled", which was true only before migration step 1. Source: `docs/DESIGN_PLATFORMS.md`, "8. Findings worth remembering" (stale on this point); `CHANGELOG.md`, "[0.2.0-beta.3] Changed".
- `gh pr edit` fails here with a Projects (classic) deprecation error; use `gh api -X PATCH`. Source: `CLAUDE.md`, "Git and PRs".
- `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --workspace --locked` fails on exactly one item once the 10 broken-link comments are fixed (2026-10-16): `<INDEX>` in `/// Target monitor selector (<INDEX>, ...)` (`src/cli/args.rs:43`) is both clap's `--help` text for `--monitor` and rustdoc's "unclosed HTML tag". It cannot be fixed comment-only without changing `--help`, so the docs build adds `-A rustdoc::invalid_html_tags` (`RUSTDOC_FLAGS` in `crates/xtask/src/docs_site.rs`); an owner decision is open. `cargo doc` documents a binary crate with its private items, so a broken link in any private doc comment of `spawn-at` fails it. `cargo doc` also leaves old crates in `target/doc`; `docs-site` clears it first.
- Starlight 0.42.6 with Astro 7.4.0 (2026-10-16, built here): links in markdown are not rewritten, so pages link `/spawn-at/<slug>/` (the base is written out; a relative `x.md` link 404s). `autogenerate` cannot sit on a group directly (since Starlight 0.39): use `items: [{ autogenerate: { directory } }]`. `markdown.smartypants: false` still works in Astro 7.4.0 but prints a deprecation warning (the default processor reads it, `@astrojs/markdown-satteri` `satteri-processor.js`); with it on, the two hyphens of `--pivot` become an en dash before `pivot`, which `docs-check-html` catches. `npm ci --ignore-scripts` is enough to build. A page named `api` would build to `/api/index.html`, where the rustdoc output is copied, so the page is `rustdoc`. mdBook has no link checker of its own, so `docs-check-html` does the internal-link and `#id` check without network.
- xtask tests that write a script and then run it must not run in parallel with another test's fork: a child forked while the script is still open for writing gives "Text file busy" (os error 26) on exec. `docs_cli.rs` serializes them with `SCRIPT_LOCK` (2026-10-16; seen in 2 of 8 full `cargo test -p xtask` runs before the lock, in none of 25 after).
- Stale statements found while writing the site (2026-10-16): `README.md` "How well it works" cites `docs/TEST_PLAN.md` 6.22 and 6.23 but its numbers are in `docs/TEST_LOG.md` 6.23 and 6.30; `docs/DESIGN_SWAY.md` section 3 says `--anchor cursor` fails on Sway but section 12 and `src/commands/spawn.rs:92` (`unwrap_or((0, 0))`) use (0, 0); `docs/DESIGN_READY_WAIT.md` section 15 items 6 and 7 (no CI on pull requests, a `python3 -c` fallback in `install.sh`) no longer hold (`ci.yml` exists, `install.sh` has no python); `docs/legacy-gnome.md` line 1 starts with a stray `cle` before its title. Not corrected here.

- GFM splits a table cell at every `|` that has no backslash before it, even inside a code span (GitHub, the site's Sätteri processor and micromark-gfm agree), so a `|` in code in a table row must be written `\|`. Three rows of `docs/` lost cells this way until PR 67 (2026-10-19): the 12,680-character row of `docs/TEST_PLAN.md` showed 2,098 of its characters. A row with fewer cells than the header gets empty cells at the end; extra cells are dropped. `cargo xtask docs-check-src` does not catch this.
- Markdown inside raw HTML renders only when blank lines surround it (a `<dd>` on one line shows `**x**` as text), and a `<p>` then appears inside the element. Converting a table in the built HTML (as `records.mjs` does) avoids writing such wrappers from the mirror. A long inline code piece (`.code-any`) is 12px wider than its column inside a block that has no padding, because the chip adds 6px on each side; `records.css` shortens it by 0.75rem. Measured 2026-10-19 in a scratch build of `docs-site` with Chrome 153.
- Cards (`records.css`, measured 2026-10-19 with Chrome 153): the short fields are shown first with CSS `order`, so keyboard focus follows the table order, not the screen order; a link in a long field is reached before one in a short field that is drawn above it (checked by Tab on a scratch page). On the real pages no card has links in two fields that swap places (0 of 297 cards; 91 cards reorder fields). `--sl-font-mono` is not defined by Starlight unless a site sets it, so `font-family: var(--sl-font-mono)` falls back to the inherited font; use `--sl-font-system-mono`. Starlight indents every `<dd>` by 1rem (`padding-inline-start`), reset in `records.css`. A selector such as `.record-key :not(pre) > code` matches nothing when the `code` is a direct child of `.record-key`; write `.record-key code`.
